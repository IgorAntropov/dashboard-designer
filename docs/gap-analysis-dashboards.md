# Что нужно Panelka, чтобы собирать дашборды уровня референса

Разбор по мотивам дашборда Ростуризма (`dashboard_v30`): 8 страниц-дашбордов
(Основные показатели, Транспорт, Средства размещения, Цены, Меры поддержки, Экономика,
Реестры, Регионы) + drill-down страницы (Динамика / Динамика по регионам / Топ регионов /
карта регионов РФ).

Цель Игоря: «каждый пункт меню = 1 дашборд», и любой из них должен собираться в нашем
конструкторе. Плюс настраиваемая карта (мир → страна → регион → область), а не только
целый мир.

---

## 1. Из чего собран референс (инвентарь «кирпичиков»)

| Кирпичик | Где встречается | Что делает |
|---|---|---|
| **KPI-плитка с дельтой** | везде | крупное значение + единица + период + бейдж дельты к АППГ (▲/▼ %, зелёный/красный) + i-тултип с источником и методикой |
| **KPI с целью/прогрессом** | Экономика (2,8% → 5% к 2030), КСР | плитка + прогресс-бар к целевому значению |
| **Линия-сравнение** | почти каждый показатель (drill-down `index_compare_monthly`) | 2–3 серии: 2023 (сплошная), 2024 опер. (сплошная), 2024 оценка (**пунктир/прогноз**), ось по месяцам |
| **План/Факт, Всего/Классиф.** | Меры поддержки, КСР | две серии на одном графике + легенда |
| **Рейтинг Топ-N** | Основные, Цены, Меры поддержки | ранг + название + дельта% + значение + инлайн-бар; блоки «Лидеры / Аутсайдеры» |
| **Карта регионов РФ (хороплет)** | Регионы, Динамика по регионам | раскраска субъектов РФ по значению, флаги регионов, тултип |
| **Таблица данных** | Регионы, Динамика | сортируемые колонки (Год ▼, Регион ▼, по годам 2002–2023), футер «РФ» |
| **Структура/разбивка** | КСР (по звёздности 5\*..1\*, по типам), Меры поддержки | категории + значение + доля %, часто как список или пончик |
| **Флаги регионов** | таблицы, карта | SVG-иконка на строку |
| **Легенда дашборда** | шапка каждой страницы | пояснение обозначений (дельта, годы, пунктир-прогноз) |
| **Секции/заголовки** | Транспорт (Авиа/ЖД), КСР (КСР/Номера) | группировка виджетов подзаголовками |
| **Модалка Импорт/Экспорт** | каждая страница | скачать xls/pdf по каждому показателю + загрузить файл |
| **Drill-down с вкладками** | клик по плитке | переход на страницу показателя с табами Динамика / По регионам / Топ |
| **Скачивание представления** | drill-down | pdf «Представление» + xls «Все данные» |
| **Тоггл данных** | drill-down | Годовые / Оперативные, выбор показателя |

---

## 2. Что у нас уже есть

- Виджеты: bar, line, area, pie, donut, scatter, radar, gauge, progress, stat-tile, text, svg-map
  (схематичная карта-континенты).
- Общий rendering core (ECharts) — один движок на редактор и embed.
- Темы (5), i18n (7 языков), embed (iframe / web-component / npm), режимы данных
  runtime / pull / live.
- Модель данных: **один плоский массив на виджет**, биндинг `ключ → колонка` (label + value).
- Конфиг-панель: переименование ключей, тип поля, один dataKey на поле, title, max (gauge/progress).

Итог: у нас есть «графики по одному ряду данных». Референс же держится на **KPI-плитках с
дельтами, мульти-серийных сравнениях, рейтингах, таблицах и хороплет-карте** — почти всего
этого у нас нет.

---

## 3. Чего не хватает — главный список

### 3.1 Виджеты (типы визуализации)
1. **KPI-плитка «показатель»** — значение + единица + период + **дельта к прошлому периоду**
   (▲/▼ %, цвет по знаку) + i-тултип (источник/методика). Сейчас stat-tile умеет только
   значение+подпись. Это самый частый блок референса.
2. **KPI с целью и прогрессом** — целевое значение + прогресс-бар (у нас progress есть, но без
   «цели к дате» и подписи).
3. **Мультисерийные графики** — 2–3 ряда на одном графике (наш core рисует ровно один ряд).
   Нужны: несколько value-колонок, легенда, стиль на ряд.
4. **Пунктир/прогноз-серия** — отдельный стиль для «оценки/прогноза» (dashed), combo bar+line.
5. **Рейтинг Топ-N (список)** — ранг + имя + дельта% + значение + инлайн-бар, «Лидеры/Аутсайдеры».
   Виджета нет вообще.
6. **Таблица данных** — сортируемые мультиколоночные таблицы. Виджета нет.
7. **Структура/разбивка** — категории + доля %, как стек-бар/пончик/список с процентами.
8. **Горизонтальный и стек-/100%-бар** — сейчас только вертикальный одиночный бар.
9. **Настоящая хороплет-карта** — субъекты РФ (85), мир по странам, с реальной геометрией.
10. **Иконки/флаги в строках** таблиц и карты.

### 3.2 Настройка виджетов
1. **Карта: выбор охвата** — мир (страны) → континент → страна → регион/область. Это прямой
   запрос Игоря. Нужны библиотека карт + селектор охвата + зум/roam.
2. **Мультибиндинг** — привязать несколько value-колонок (серий), не только label+value.
3. **Стиль на серию** — цвет, тип (bar/line), пунктир, легенда on/off.
4. **Формат чисел** — единицы (тыс./млн/₽/%), разделители, знаки после запятой, форматтер оси.
5. **i-описание** — источник + методика (тултип), подпись периода, база дельты (АППГ).
6. **Цель/план + пороги** — целевое значение, покраска по знаку (зелёный/красный).
7. **Сортировка / Top-N** — для рейтинга и таблицы.

### 3.3 Модель данных / контракт
1. Сейчас **один плоский массив + label/value**. Референсу нужно: несколько метрик в строке,
   временной ряд с категориями, несколько именованных серий, значения по регионам, период
   сравнения (текущий vs АППГ), прогноз/план. → расширить контракт: `measures[]`, `series[]`,
   ось категорий.
2. **Производные поля** — дельта %, доля %, прогресс к цели. Нужен слой трансформаций.
3. **Форматирование/локаль** чисел в контракте.

### 3.4 Уровень дашборда (чтобы собрать целую страницу)
1. **Секции-контейнеры с заголовками** на холсте (Транспорт → Авиа/ЖД). Есть только text-block.

> Из списка исключено (по решению Игоря): мультистраничные дашборды (меню = страницы),
> drill-down, модалка Импорт/Экспорт по показателю и PDF-«представление»/печать — не нужны.

### 3.5 Карта — отдельно (и почему сейчас «не рисуется»)
- Текущая `svg-map` — это **схематичные 6 континентов**, зашитый SVG. Для задач Игоря
  (регионы РФ, страна/область) это тупик: нет реальной геометрии, нет 85 субъектов.
- Рендер, скорее всего, не появляется из-за связки «`series-map` + SVG-карта» (ненадёжный путь
  в ECharts) и/или нулевого размера контейнера на момент init.
- **Правильный путь:** перейти на **GeoJSON-карты** через `echarts.registerMap(name, geoJson)` —
  это стандартный, надёжный хороплет. Нужны:
  1. Реестр карт: мир (страны), РФ (субъекты), при желании — федеральные округа и отдельные
     страны/области; возможность добавлять новые.
  2. Селектор охвата в конфиг-панели (`config.map` = world / ru / ru-<округ> / <country>…).
  3. Биндинг `регион → значение` + нормализация названий (RU/EN алиасы), visualMap-легенда,
     тултип, зум/roam.
  4. Источник GeoJSON: бандлить компактные + подгружать детальные по требованию (в проде сеть
     есть; в песочнице — нет, поэтому качать/бандлить будем на твоей стороне).

## 4. Предлагаемая дорожная карта (по ценности)

Разбито на вертикальные итерации (в духе §17.3). Порядок — от самого частого блока к сложному.

1. **KPI-плитка 2.0** — значение + единица + период + дельта(▲/▼%) + i-тултип + (опц.) цель/прогресс.
   Закрывает ~половину плиток во всех 8 дашбордах.
2. **Мультисерии + легенда + формат чисел** — расширить контракт и core на N серий, пунктир для
   прогноза, единицы/разделители. Открывает сравнения 2023/2024/прогноз и План/Факт.
3. **Рейтинг Топ-N (список-виджет)** — ранг/имя/дельта/значение/инлайн-бар, Лидеры/Аутсайдеры.
4. **Таблица данных** — сортируемая мультиколоночная.
5. **Карта на GeoJSON + выбор охвата** — мир/страна/регион, РФ по субъектам, зум, легенда,
   нормализация имён. (Здесь же чиним «карта не рисуется», заменяя схему на GeoJSON.)
6. **Секции-контейнеры и заголовки** на холсте.

Статусы: пункты 1–6 сделаны (KPI 2.0, мультисерии, рейтинг, таблица, карта GeoJSON; секции — в работе).
Дальше по плану: кастомные темы, аналитика встраиваний.

> Из плана исключено (по решению Игоря): мультистраничные дашборды (меню = страницы) и drill-down.

---

## 5. Что стоит решить перед стартом
- Порядок итераций (что берём первым — KPI-плитка, мультисерии, рейтинг, карта?).
- Карта: какие карты бандлим (РФ-субъекты + мир-страны как база?), откуда берём GeoJSON,
  нужен ли уровень «федеральные округа» и отдельные страны/области.
- Формат/локаль чисел: RU-разделители по умолчанию, единицы как свободный текст?
- Мультистраничность: делаем «страницы внутри дашборда» или «виджет-меню, ссылающийся на
  другие дашборды»?
